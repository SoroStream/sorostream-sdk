Add batch reads, request deduplication, and an RxJS-compatible reactive interface:

- **#427** New `client.getStreams(ids)` fetches many streams in a **single** RPC call (`get_streams`) instead of one call per ID, plus `client.getStreamsBatch(ids)` which additionally reports `missing`, `cached`, and `rpcCalls`. Requests are chunked (default 50 IDs per call, configurable per call via `chunkSize` or globally via the new `batchReadSize` client option), duplicate IDs are collapsed, results keep the requested order, cached IDs skip the network, and fetched streams warm the per-stream cache. Missing IDs are reported instead of failing the batch (opt into `StreamNotFoundError` with `{ strict: true }`), and contracts without the batch entry point transparently fall back to parallel single reads. `MockSoroStreamClient` implements the same API.
- **#426** All read paths (`getStream`, `getStreams`, `getClaimable`, `getStreamsBySender`, `getStreamsByRecipient`, `getTokenMetadata`) now share one `RequestDeduplicator`: concurrent calls addressing the same data join a single in-flight RPC request instead of issuing one each, and every joined caller receives the same resolved value. Failures are never cached, in-flight tracking is dropped on `setNetwork`/`updateConfig`, a `requestDeduplicated` event is emitted through the event bus, and `getRequestStats()` / `resetRequestStats()` / `clearInFlightRequests()` expose the behaviour. Opt out with `{ dedupeRequests: false }`. `getStream` also accepts `{ refresh: true }` to bypass the TTL cache while still deduplicating.
- **#423** New `client.observeStream(id)` and `client.observeClaimable(id)` return an RxJS-compatible observable (`SoroStreamObservable`) that emits the current value on subscribe and again on every change. They implement the Observable interop protocol (`Symbol.observable`), so `from(client.observeStream(id))` composes with the full RxJS operator set — while RxJS stays out of the SDK's dependencies. Subscribers of the same stream share one reference-counted poll loop with replay of the latest value, the loop is torn down when the last subscriber leaves (and by `destroy()`), and the observable completes when a stream reaches a terminal state. `shareLatest()` and the observable primitives are exported for building custom reactive sources; `MockSoroStreamClient.observeStream()` provides the same interface in tests.
